## 1. 产品概述

### 1.1 一句话定位

**股票数据采集展示系统**是一套面向个人价值投资者的本地化标的深度分析工具——不是通用看盘软件，而是帮助用户对单只股票进行"产业背景→财务数据→市场表现→竞争格局"全方位梳理的私密分析工作台。

### 1.2 目标用户

| 画像 | 描述 | 核心需求 |
|------|------|---------|
| **个人价值投资者（主力）** | 30-50岁，有3年以上投资经验，注重基本面分析，持有周期以季度/年计 | 需要对持仓标的做系统化深度研究，而非盯盘；所有数据和分析集中在一处 |
| **独立研究员（次级）** | 专业背景，可能覆盖多个行业，需要结构化分析框架 | 需要灵活的数据组织方式，支持跨行业对比，有导出需求 |

### 1.3 用户痛点

1. **数据分散**：基本面数据（财报、估值、股东）分散在东方财富、同花顺、雪球等多个平台，反复切换效率低
2. **分析碎片化**：研究笔记散落在备忘录、Notion、Excel 各处，无法与行情数据关联
3. **缺少结构**：初学者不知道从哪些维度分析一只股票，需要引导式框架
4. **竞品对比难**：手动收集竞品数据做对比，耗时长且容易遗漏

### 1.4 成功标准（可量化）

| 编号 | 标准 | 目标值 | 测量方式 |
|------|------|--------|---------|
| SC-1 | 添加股票后自动数据就绪时间 | ≤ 30秒（基本信息）+ ≤ 5分钟（全部8类自动数据） | 计时 |
| SC-2 | 自动数据获取成功率 | ≥ 95%（含降级到新浪源的场景） | 统计 FAILED/总数 |
| SC-3 | 单只股票完整分析耗时 | ≤ 30分钟（自动数据 + 手动补充） | 用户测试 |
| SC-4 | 分析完成度可度量 | 14项检查项（8自动 + 6手动），百分比展示 | 系统统计 |
| SC-5 | API 响应 P95 | 列表页 ≤ 200ms，详情页 ≤ 500ms | 性能测试 |

### 1.5 明确不做（边界清单）

| 不做 | 原因 |
|------|------|
| ❌ 自动交易/连接券商 | 聚焦分析，不涉及资金操作 |
| ❌ 量化回测 | 不是策略回测工具 |
| ❌ 组合管理/资产配置 | 单标的深度分析，不做多股票组合优化 |
| ❌ 实时盯盘/秒级刷新 | 最低刷新间隔 5 分钟，非高频工具 |
| ❌ 社区/分享/多用户 | 本地单用户工具，数据私密 |
| ❌ 多股票横向对比面板 | 仅支持"竞品对比"功能，不做批量选股对比页 |
| ❌ 行业估值中位数自动获取 | 无可用数据源，改为手动录入 |
| ❌ 行业资金流向自动获取 | `stock_fund_flow_industry` 未验证，暂不纳入 |

## 4. 验收标准（每个功能可测试的通过条件）

### 4.1 标的管理

| 验收项 | 通过条件 |
|--------|---------|
| 添加股票 | 输入合法6位代码 → 返回 201 + stock JSON（含 id/code/name/industry） → 异步触发8步初始化 |
| 添加股票-代码校验 | 输入非6位数字 → 返回 400 + "股票代码格式错误"；输入不存在代码 → 返回 400 |
| 添加股票-去重 | 重复添加已存在代码 → 返回 409 + "股票已存在" |
| 删除股票 | DELETE → 返回 204 → 级联删除16张关联表数据 → 查询确认记录数为0 |
| 列表 | GET → 返回 active=true 的股票列表，含 latest_price、change_percent、completeness |

### 4.2 标的概览

| 验收项 | 通过条件 |
|--------|---------|
| 详情 | GET /stocks/{id} → 返回完整 stock 对象（含估值字段 pe_ttm/pb/ps_ttm/peg 非 null） |
| 初始化状态 | GET /stocks/{id}/init-status → 返回8步状态，status 为 PENDING/IN_PROGRESS/DONE/FAILED |
| 完成度 | GET /stocks/{id}/completeness → 返回百分比 + 14项逐项状态 + missingItems 列表 |

### 4.3 财务数据

| 验收项 | 通过条件 |
|--------|---------|
| 利润表 | GET /stocks/{id}/income → 返回数组，每项含 report_date、parent_net_profit、total_revenue、operating_cost，值单位为元 |
| 财务摘要 | GET /stocks/{id}/financial → 返回数组，每项含 eps、roe、gross_margin、debt_ratio 等14个指标 |
| 主营构成 | POST → 创建成功返回 201；PUT → 更新成功；DELETE → 返回 204 |

### 4.4 市场行情

| 验收项 | 通过条件 |
|--------|---------|
| K线 | GET /stocks/{id}/kline?period=daily → 返回数组 ≥ 200条，含 open/close/high/low/volume |
| 技术指标 | GET /stocks/{id}/indicators → 返回数组，含 ma5/ma10/ma20/ma60/macd/rsi/kdj_k/kdj_d/kdj_j/boll_upper/mid/lower |
| 资金流向 | GET /stocks/{id}/fund-flow → 返回数组，含 main_net_amount、huge/big/mid/small 净额和占比 |

### 4.5 手动数据

| 验收项 | 通过条件 |
|--------|---------|
| 产业分析 PUT | 提交合法 JSON → 返回 200 + 保存后的对象 → 再次 GET 返回相同数据 |
| 产品构成 POST | revenue ≥ 0, revenue_ratio 0-100 → 201；违反任一 → 400 + 字段级错误提示 |
| 笔记 POST | content 1-10000 字符, category 合法枚举 → 201；违反 → 400 |

### 4.6 预警

| 验收项 | 通过条件 |
|--------|---------|
| 价格预警触发 | 设置 ABOVE 100 → 股价更新到 101 → is_triggered 变为 true → 前端显示预警 |

## 5. 非功能性需求

| 类别 | 要求 |
|------|------|
| **性能** | 列表页 P95 ≤ 200ms；详情页 P95 ≤ 500ms；K线图渲染 ≤ 500ms（250点） |
| **可靠性** | 外部 API 失败不崩溃，降级显示缓存数据或"暂不可用" |
| **安全** | 所有服务绑定 127.0.0.1；XSS 过滤所有手动输入；JPA 参数化查询防注入 |
| **可用性** | 前端骨架屏 + 加载进度；空状态引导；字段级表单校验错误提示 |
| **数据** | H2 文件持久化 ~/stock-trading/db；100只股票×5年 ≈ 84MB；单表查询 < 50ms |

## 7. v2.0 变更记录（2026-07-29）

> v1.0 之后系统实际演进已超出「单标的分析工作台」范畴，向「个人智能投研平台」（对标开盘啦类产品的个人版）扩展。本章为追加式变更记录，v1.0 正文（§1~§6）保持原样作为历史基线，冲突处以本章为准。

### 7.1 边界清单更新（对 §1.5 的修订）

| 原边界 | v2.0 调整 | 说明 |
|--------|-----------|------|
| ❌ 组合管理/资产配置 | ⚠️ 部分放开：**做自选股与组合诊断，仍不做资产配置/仓位优化** | 自选股支持分组/标签管理；智能体工作流可对自选池做组合诊断点评；不涉及仓位建议与再平衡 |
| ❌ 多股票横向对比面板 | ⚠️ 部分放开：市场中心提供涨停/龙虎榜/资金流全市场榜单 | 仍不做自由拖拽式批量选股对比页 |
| ❌ 自动交易/连接券商 | ✅ 维持不做 | 聚焦分析，不涉及资金操作 |
| ❌ 量化回测 | ✅ 维持不做 | 不是策略回测工具 |
| ❌ 实时盯盘/秒级刷新 | ✅ 维持不做 | 预警扫描 5 分钟级，非高频 |
| ❌ 社区/分享/多用户 | ✅ 维持不做 | 本地单用户，数据私密 |
