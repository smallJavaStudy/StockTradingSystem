# 开发流程规范

## 流程总览

```
需求定稿 → 概要设计 → 概要设计自检 → 详细设计 → 详细设计自检 → 编码 → 单元测试 → 代码审查 → 阶段回归 → E2E测试
```

## 步骤明细

### 步骤0：需求定稿

- 运行需求自检SKILL，确认所有"不通过"项已修复
- 确认所有"有风险"项已有应对方案或已接受
- 需求文档冻结，后续变更走需求变更流程（记录变更原因、影响范围、涉及文档）

### 步骤1：概要设计

- 输出文件：`system-planner/high-level-design.md`
- 内容包括：
  - 系统架构图（组件、依赖关系、数据流向）
  - 模块划分（每个模块的职责和边界）
  - 接口契约（模块间调用协议、请求/响应格式）
  - 数据流图（数据从源到存储到展示的完整路径）
  - 技术选型理由
  - 关键设计决策和trade-off

### 步骤2：概要设计自检SKILL

- 输出文件：`system-planner/hld-checklist/SKILL.md`
- 检查项类别：
  - 架构合理性（模块边界是否清晰、耦合度是否可控）
  - 接口一致性（模块间接口是否对齐、字段是否匹配）
  - 数据流完整性（每类数据从源到展示的路径是否闭环）
  - 可扩展性（新增数据源/新增分析模块的改造成本）
  - 性能瓶颈识别
  - 与需求的一致性（每个需求功能在设计中是否有对应方案）

### 步骤3：运行概要设计自检

- 对 high-level-design.md 逐项过检查清单
- 修复"不通过"项后才进入下一步
- "有风险"项记录到文档并评估是否可接受

### 步骤4：详细设计

- 输出文件：`system-planner/detailed-design.md`
- 内容包括：
  - 类设计（类名、职责、依赖关系）
  - 方法签名（入参、返回值、异常）
  - 字段映射（外部接口字段 → Python服务字段 → Java DTO字段 → DB字段）
  - SQL DDL（建表语句、索引、约束）
  - 前端组件树和路由
  - 状态管理结构
- **追溯矩阵**：每条详细设计标注对应概要设计的编号（如 HD-01, HD-02），改动时按编号联动更新概要设计

### 步骤5：详细设计自检SKILL

- 输出文件：`system-planner/dd-checklist/SKILL.md`
- 检查项类别：
  - 类职责单一性
  - 方法签名完整性（参数校验、异常处理、返回值类型）
  - 字段映射正确性（源字段 → 目标字段，精度、类型、空值处理）
  - SQL合理性（索引、约束、查询性能）
  - 与概要设计的追溯完整性（每条详细设计都有概要设计对应）
  - 与API设计的一致性（字段名、类型、枚举值对齐）

### 步骤6：运行详细设计自检

- 对 detailed-design.md 逐项过检查清单
- 修复"不通过"项后才进入编码

### 步骤7：编码开发

- 按实施阶段顺序开发
- 严格遵守详细设计中的类名、方法签名、字段名
- 如发现设计问题，先更新详细设计再编码（保持追溯矩阵同步）

### 步骤8：单元测试

- 每个功能编码完后**立即**编写单元测试
- 后端：JUnit 5 + Mockito，覆盖 Service 层核心逻辑
- Python：pytest，覆盖数据转换和错误处理
- 前端：Vitest，覆盖组件渲染和 Store 状态变更
- **运行测试并全部通过后才标记该功能完成**

### 步骤9：代码审查 + lint/typecheck

- 运行 lint：Java（checkstyle/spotbugs）、Python（ruff/flake8）、JS（eslint）
- 运行 typecheck：Java（编译检查）、Python（mypy）、TS（tsc）
- 人工审查重点：安全漏洞（XSS/注入）、性能隐患（N+1查询）、规范违反

### 步骤10：阶段回归测试

- 每个实施阶段完成后，运行全量已有功能的测试
- 确保新功能未破坏已有功能
- 如有回归，修复后才进入下一阶段

### 步骤11：Playwright 端到端测试

- 全系统功能开发完成后执行
- 测试范围：

| 类别 | 内容 |
|------|------|
| 功能可达性 | 每个页面/Tab正常加载，无白屏/报错 |
| 数据返回验证 | API返回非空数据，结构正确 |
| 数据格式验证 | 字段类型、格式、范围符合设计（日期ISO格式、金额数字、百分比0-100） |
| CRUD完整性 | 创建→查询→更新→查询→删除→查询 全链路 |
| 空数据/错误状态 | 无数据时展示正常，不崩溃 |
| 跨页面一致性 | 同一数据在不同页面一致 |
| 表单校验 | 非法输入被拦截，错误提示具体可操作 |
| 初始化流程 | 添加股票后数据逐步加载完成 |
| 竞品联动 | 添加竞品后数据自动拉取并展示 |
| 预警触发 | 价格达到阈值时预警状态变化 |
| 导航与交互 | 页面跳转、Tab切换、弹窗关闭正常 |
| 数据过期标记 | 接口失败时缓存数据旁显示过期标记 |

## 流程规则

1. **不跳步**：每个步骤必须完成且通过检查后才进入下一步
2. **文档先行**：先更新设计文档再写代码
3. **追溯联动**：详细设计改动时，同步更新概要设计和追溯矩阵
4. **测试同步**：编码和单元测试同步进行，不延后
5. **变更记录**：需求/设计变更时记录变更日志
