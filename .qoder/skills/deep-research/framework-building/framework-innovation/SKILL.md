# 分析框架创新

## 何时使用

- 现有分析框架对一个重要现象的解释力持续下降
- 市场在用旧框架定价，但底层逻辑已经变了
- 需要构建一个新的分析体系来捕捉旧框架漏掉的价值

## 框架创新四步法

### 1. 诊断旧框架的失效点

| 失效模式 | 症状 | 案例 |
|---------|------|------|
| 漏变量 | 框架缺了一个关键驱动因素 | "度电成本"漏了"架构价值"；"模型分数"漏了"任务完成度" |
| 错量纲 | 在用错误的单位衡量价值 | 用"参数数"衡量AI竞争力而不是"产品力" |
| 静态假设 | 框架假设底层条件不变 | "制程中心论"假设缩微是唯一路径，忽略了系统级优化 |
| 线性外推 | 框架假设线性关系 | "产能翻倍=利润翻倍"忽略了有效产能折扣 |

### 2. 引入新维度

新维度必须满足：
- **未被旧框架度量**：如果旧框架已经考虑了这个维度，那不需要新框架
- **有可验证的证据**：不是纯理论，有数据/案例支撑
- **能解释旧框架解释不了的现象**：这是检验标准

### 3. 新旧框架对比检验

拿3-5个案例，分别用旧框架和新框架做判断：

| 案例 | 旧框架判断 | 新框架判断 | 实际结果 | 哪个更准 |
|------|-----------|-----------|---------|---------|

### 4. 设定新框架的适用边界

没有万能的框架。明确：
- 什么条件下新框架有效
- 什么条件下新框架也会失效

## 典型案例

| 领域 | 旧框架 | 新框架 | 核心创新 |
|------|-------|-------|---------|
| 半导体进步 | 制程中心论（纳米数） | 系统效率中心论（系统总时间，韬定律v2） | 从"晶体管缩微"到"系统联动" |
| 算力估值 | GPU数量×单价 | 每美元Capex可计费Token | 从"买了多少卡"到"每块钱能产出多少可计费Token" |
| AI互联网 | 模型分数/参数 | 产品力/任务完成度 | 从"能不能说"到"能不能把事办完" |
| 半导体材料 | 单品纯度 | 平台协同验证能力 | 从"一个产品做多纯"到"多个产品能否一起验证" |

## 输出格式

```
领域: [领域]
旧框架: [描述+为什么失效]
新框架: [核心逻辑+新引入的维度]
关键检验: [用哪个案例来检验新框架优于旧框架]
适用边界: [什么条件下有效/什么条件下可能失效]
投资含义: [新框架下哪些标的会被重估]
```
