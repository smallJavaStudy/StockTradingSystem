# 概要设计自检清单

## 使用方式

对项目的概要设计文档（high-level-design.md）逐项过以下检查清单，输出一份自检报告。
每条检查给出：✅ 通过 / ⚠️ 有风险 / ❌ 不通过，附具体问题说明。
同时交叉参考需求文档（SKILL.md、api-design.md、data-fetcher.md），确认设计与需求一致。

---

## 一、架构合理性

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| A1 | 系统分层是否清晰？ | 每层职责明确，不越层调用（如前端不直接调外部API、后端不直接调东方财富） |
| A2 | 模块边界是否清晰？ | 每个模块职责单一，模块间无循环依赖，接口是唯一的交互方式 |
| A3 | 模块耦合度是否可控？ | 模块间通过接口/协议通信，不直接依赖内部实现；一个模块变更不迫使多个模块改动 |
| A4 | 是否有单点故障？ | 关键路径上无单点（如限流器是瓶颈但有降级方案） |
| A5 | 新增功能的改造成本是否可控？ | 新增一类数据源或一个分析模块，改动不超过3个模块 |

## 二、接口一致性

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| I1 | 前后端接口是否完整对齐？ | 前端每个功能需要的API在后端都有对应端点，后端每个端点都有前端调用方 |
| I2 | 后端与Python服务接口是否完整对齐？ | 后端每个需要外部数据的场景在Python服务都有对应端点，Python每个端点都有后端调用方 |
| I3 | 接口契约是否包含完整信息？ | 每个接口定义了：路径、方法、请求参数、响应结构、错误码 |
| I4 | 接口命名是否一致？ | 同一概念在不同层使用一致的命名（如stockId不混用id/stockId/pk） |
| I5 | 枚举值在前后端是否一致？ | lifecycle_stage、moat_level、alert type等枚举值前后端完全匹配 |

## 三、数据流完整性

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| D1 | 每类自动数据是否有完整的"源→存储→展示"路径？ | 外部接口→Python→Spring Boot→DB→前端，每一步都有对应模块负责 |
| D2 | 每类手动数据是否有完整的"输入→校验→存储→展示"路径？ | 前端表单→Controller→Service(校验+XSS过滤)→Repository→前端展示 |
| D3 | 数据初始化流程是否覆盖所有数据类型？ | 添加标的后初始化步骤的数量 = 自动数据表的数量 |
| D4 | 数据同步/刷新是否有遗漏？ | 每类自动数据都有对应的定时任务或触发机制 |
| D5 | 数据流向是否有断点？ | 无数据"只写不读"或"只读不写"的断路（每个DB写入都有读取方，每个展示都有数据来源） |

## 四、与需求的一致性

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| R1 | 需求中的每个功能模块在设计中是否有对应？ | SKILL.md 8个核心功能在设计中有完整的架构支撑 |
| R2 | 需求中的每个数据表在设计中是否有对应？ | 15张DB表的写入路径和读取路径都有设计 |
| R3 | 需求中的非功能性要求是否被设计覆盖？ | 限流、缓存、安全、日志、存储预估在设计中都有方案 |
| R4 | 需求中的"不做什么"边界在设计中有体现？ | 设计没有超出需求边界（如没有交易模块、没有回测模块） |
| R5 | 需求中的已接受风险在设计中有应对？ | 每个已接受风险有降级方案或说明 |

## 五、可扩展性

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| E1 | 新增一类外部数据源的改造量？ | 只需改动Python服务+后端Service+前端组件，不改动架构 |
| E2 | 新增一个分析维度的改造量？ | 只需新增Controller/Service/Repository/前端组件，不影响已有模块 |
| E3 | 数据库从H2迁移到PostgreSQL的改造量？ | 只需改配置（datasource URL+驱动），JPA代码无需改动 |
| E4 | 是否可水平扩展？ | 说明当前单机限制和未来扩展路径 |

## 六、性能与可靠性

| 编号 | 检查项 | 通过标准 |
|------|--------|---------|
| P1 | 是否识别了所有性能瓶颈？ | 外部API限流、大数据量计算、前端渲染等场景已识别并评估 |
| P2 | 外部依赖失败时系统是否可降级？ | 东方财富不可用→新浪降级；AKShare不可用→显示"暂不可用" |
| P3 | 限流策略是否与验证结论一致？ | 500ms间隔、IP级ban特征、datacenter与push2独立性等已体现在设计中 |
| P4 | 并发场景是否考虑？ | 多个定时任务同时运行、用户操作与定时任务冲突、竞品初始化与主股票初始化冲突 |
